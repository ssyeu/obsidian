Computer architecture: decoder that only understands binary, disk storage stores primary data, its non volatile so it can maintain data without power. Ram is the primary data holder for data that is in use, when a program runs it uses ram to quickly read and write. It's volatile so it needs power to keep its memory. Cache is smaller than ram but even faster than ram, goal is to reduce average time to access data by leaving data that is quickly needed in the cache. CPU is the brain of the computer, high level languages need to be compiled into basic code before being given to the CPU. The motherboard is what lets the data flow between all these parts.

CI/CD lets code go from our computer to a server that can work with a load balancer to take a lot of user requests that can maintain user experience. Then we use an external storage server to store data and can also communicate to other servers. Logging and monitoring to see how the server is running, convention is to use a different server that isnt influenced by the production server to monitor that data. If there is a problem the logging and monitoring part will flag it and point to possible causes where we can try to recreate the bug in a staging environment or test environment so users wont be affected by test environment. Once it's fixed a hotfix is rolled out before a more permanent fix can be applied.

What is good design in system design and architecture? It has to be scalable, maintainable, efficient, and planning for failure and is reliable. The key elements are moving data, storing data, and transforming data. Moving data is making sure that data can go from one part of the system to another without being tainted and be quick and secure. Storing data is being able to index quickly, access patterns, and be stored securely with backups just in case. Transforming data is turning raw data into meaningful information. 

CAP theorem, balances between three key aspects, consistency, availability, and partition tolerance. Consistency insures that all nodes have the same data and changes are reflected within all nodes. Availability is that the system is always available. Partition tolerance insures that even if there is a disruption in communication between nodes the system still works. According to CAP, a system can only do 2 of these at a time. There will be tradeoffs for every system design. It's about finding the best solution, not the perfect one. 

Availability is measured by what percent of time the server is up with 99.999% being the goal which means theres only 5 minutes of downtime a year. To achieve this we could implement things to degrade gracefully or use backups. To measure how this is done we use reliability, fault tolerance, and redundancy. Reliability is how consistent the system is, fault tolerance is how resiliant a system is to unexpected faulures, redundancy is making sure that things still work with backups even if things go wrong. Speed is measured through throughput and latency. Throughput is how many inputs a server can take at a single time or how many queries can be taken a second or bytes that can be taken per second. Latency is how long it takes to get a response per request. Optimizing for throughput can increase latency and reducing latency can lead to less throughput. These things are hard to build but even harder to change as things go on and things scale, so it is very important to make sure that everything has a solid foundation with all these concepts to reduce the chance of a rebuild being necessary and lead to a healthy system that can thrive.

Networking basics is how computers communicate with each other, IP addresses is how they realize which computer is which. Internet protocol is a set of rules that defines how data is sent and received. Application layer is data that is related to the application is stored, and the layer on the receiving device is what interprets it. Transport layer is what delivers the data reliability and makes sure the data is correct.
